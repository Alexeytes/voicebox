## Технический стек

- Python 3.11+
- FastAPI + Uvicorn (`--workers 1`, состояние в памяти)
- Jinja2, ванильный HTML/CSS/JS (без сборщиков)
- `gTTS` — основной движок
- `edge-tts` — опциональный движок (может отдавать 403, должен мягко фейлиться)
- `pydub` + `ffmpeg` — склейка mp3
- `pydantic-settings` — конфигурация
- `passlib[bcrypt]` + `itsdangerous` — пароли и сессии
- `aiosqlite` + простые репозитории — хранение пользователей, статистики, баннеров
- `bleach` — санитизация HTML-сниппетов
- `pytest` + `httpx.AsyncClient` — тесты
- `mkdocs` + `mkdocs-material` — сборка доков
- `Dockerfile` + `docker-compose.yml` — деплой

**Почему SQLite, а не Postgres:** однофайловая БД, без внешних сервисов, хватает для админки и статистики даже при сотнях тысяч записей. Архитектурно оставляй место для замены на Postgres: репозитории — простые функции без ORM-магии, миграции — чистый SQL.

**Почему aiosqlite, а не sqlmodel/SQLAlchemy:** меньше зависимостей, проще тесты, легче читать код. Репозитории возвращают dataclass-модели, а не ORM-объекты.

## Абстракция TTS-движка

`app/tts/base.py`:

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Iterable

@dataclass(frozen=True)
class Voice:
    id: str
    engine: str
    language: str
    locale: str
    gender: str
    name: str
    description: str = ""

class TTSEngine(ABC):
    name: str
    supports_preview: bool = True

    @abstractmethod
    def list_voices(self) -> Iterable[Voice]: ...

    @abstractmethod
    async def synthesize(self, text: str, voice_id: str) -> bytes: ...
```

Требования:
- `synthesize` асинхронный снаружи, блокирующие вызовы через `asyncio.to_thread`.
- Ошибки движка логировать, не ронять сервис.
- `edge_engine` при 403 / `NoAudioReceived` возвращает понятное исключение.
- `registry.py` собирает голоса всех движков в один список.

## API: админка

Все роуты `/admin/*`, кроме `/admin/login`, требуют cookie-сессии. При отсутствии — редирект на `/admin/login` для GET, 401 JSON для POST/PUT/DELETE.

### Авторизация

- `GET /admin/login` — форма.
- `POST /admin/login` — form-data: `username`, `password`. Успех → cookie `vb_session` (HttpOnly, SameSite=Lax, Secure при `HTTPS_ONLY=true`), редирект на `/admin/`.
- `POST /admin/logout` — сброс cookie.
- Первый админ создаётся при первом старте из `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Если пользователь уже есть — не перезаписывать.
- Пароли — bcrypt через `passlib`. Сессии — `itsdangerous.URLSafeTimedSerializer`, срок 7 дней.
- Brute-force: 5 неудачных попыток на IP за 15 минут → 429 на следующие 15 минут.

### Статистика

- `GET /admin/stats` — HTML-дашборд.
- `GET /admin/api/stats/overview` — JSON за 24ч / 7д / 30д.
- `GET /admin/api/stats/timeseries?metric=synthesis&range=7d` — точки для графика.
- `GET /admin/api/stats/events?limit=100&offset=0` — лог событий.
- `GET /admin/api/stats/export.csv` — экспорт в CSV.

События: `synthesis_requested`, `synthesis_done`, `synthesis_error`, `preview_requested`, `preview_done`, `voice_selected`, `banner_shown`, `banner_clicked`, `login_success`, `login_failed`, `admin_action`.

Схема `stats_events`: `id`, `ts`, `event_type`, `ip_hash` (SHA-256 от IP + `IP_HASH_SALT`), `lang`, `voice_id`, `engine`, `duration_ms`, `status`, `meta_json`.

### Баннеры

CRUD в `/admin/banners`:
- Поля: `title`, `image_url` или `image_upload`, `target_url`, `alt_text`, `weight`, `active_from`, `active_to`, `enabled`, `position`, `html_snippet`.
- Позиции: `top`, `sidebar`, `bottom`, `between`.
- Загрузка картинок → `data/banners/{uuid}.{ext}`, лимит 2 MB, разрешены `png`, `jpg`, `jpeg`, `gif`, `webp`. MIME по содержимому, не по расширению.
- Рендер: `<a href="/go/banner/{id}" rel="noopener sponsored" target="_blank"><img src="..." alt="..."></a>`.
- `GET /go/banner/{id}` — пишет `banner_clicked`, редиректит 302 на `target_url`.
- Выбор баннера: фильтр по `enabled` и расписанию, случайно с весами. Если активных нет — слот не рендерится.

### Настройки

`GET/POST /admin/settings` — runtime-настройки (key-value): `default_lang`, `banner_rotation_interval`, `maintenance_mode`, `announcement_text`. Не дублировать `.env`.

## Безопасность админки

- Все `/admin/*` и `/admin/api/*` требуют сессии. Rate limit: 30/60 сек на IP для read-only, 10/60 сек на write.
- CSRF: для POST/PUT/DELETE — проверка `Origin`/`Referer` + double-submit cookie `vb_csrf`.
- Cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` при `HTTPS_ONLY=true`, `Path=/admin`.
- Картинки баннеров: имя `^[a-f0-9]{32}\.(png|jpg|jpeg|gif|webp)$`.
- HTML-сниппеты через `bleach`, whitelist: `a`, `img`, `div`, `span`; атрибуты `href`, `src`, `alt`, `style` с ограниченным набором CSS.
- Аудит: каждое действие в админке пишет `admin_action` в stats.

## Качество кода

- `from __future__ import annotations`, полная типизация, Pydantic-модели.
- Логирование через `logging`, формат: `%(asctime)s %(levelname)s %(name)s: %(message)s`.
- Каждый внешний вызов в try/except с понятным сообщением.
- Роуты тонкие, бизнес-логика в сервисах.
- Репозитории без ORM-магии — простые функции, возвращают dataclass-модели.
- Миграции — SQL-скрипты в `db/migrations/`, применяются при старте.
- Никаких глобальных мутабельных состояний вне явных синглтонов.

Требования к докам:
- Русский для описаний, английский для имён файлов и кода.
- Относительные ссылки между файлами.
- Примеры команд — рабочие.
- Без воды.
- Оглавление в файлах > 100 строк.
- Mermaid для схем.
- Если код меняется — доки обновляются в том же коммите.

`README.md` в корне — 1 экран: что это, быстрый старт, ссылка на `docs/`.

## Порядок работы

1. Изучи `prototype/`, зафиксируй поведение.
2. Рефакторинг в новую структуру **без изменения поведения**. Проверь вручную.
3. `TTSEngine` + `gTTS`. `/synthesize` работает как раньше.
4. `/voices` + `/voices/preview`.
5. Обнови публичный UI.
6. `edge-tts` как опциональный.
7. БД, миграции, модели, репозитории.
8. Auth: пароли, сессии, `/admin/login`.
9. Stats: middleware, схема, агрегатор, дашборд.
10. Banners: CRUD, загрузка картинок, рендер, `/go/banner/{id}`.
11. Settings.
12. CLI.
13. Тесты — по ходу.
14. Docker + Makefile + mkdocs.
15. Полная документация.
16. Финальный прогон: `pytest`, `mkdocs build`, `docker compose up --build`.

На каждом шаге — коммит с осмысленным сообщением.

## Что НЕ делать

- Не подключать Celery, Redis, Postgres, Kafka.
- Не добавлять OAuth, регистрацию, роли (кроме admin/viewer).
- Не переписывать фронт на React/Vue/Svelte.
- Не запускать `uvicorn --workers > 1`.
- Не менять формат mp3.
- Не менять сигнатуры публичных эндпоинтов без причины.
- Не выкидывать `prototype/`.
- Не использовать сторонние UI-фреймворки для админки (Bootstrap, Tailwind через сборку). Chart.js через CDN — можно.

## Финал

Когда все критерии готовности выполнены:

1. Прогони `pytest -v`, `mkdocs build`, `docker compose up --build`. Зафиксируй результаты.
2. Запусти `uvicorn app.main:app --host 127.0.0.1 --port 8000 &` в фоне, проверь `curl`-ом ключевые эндпоинты, убей процесс.
3. Сделай финальный коммит: `chore: release v0.3.0`.
4. Выведи пользователю отчёт:
   - Что сделано (по пунктам критериев).
   - Известные ограничения.
   - Команды для запуска локально, в Docker, для сборки доков.
   - Пароль админа по умолчанию (из `.env.example`) и напоминание его сменить.
   - Ссылку на `docs/index.md`.

Работай автономно. Если что-то противоречиво — прими решение и запиши в «Принятые решения» `docs/development.md`. Останавливайся только на блокирующих проблемах.

**Начинай с Фазы 0.**
