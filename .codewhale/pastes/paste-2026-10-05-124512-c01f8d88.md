# Промпт для кодинг-агента: TTS-сервис «под ключ» + админка (v2, автономный запуск)

Скопируй всё, что ниже, и вставь первым сообщением в чат кодинг-агента (Cursor, Claude Code, Aider, Continue, Cline и т.п.). **Предварительная подготовка не нужна** — агент сам создаст структуру, проверит окружение, инициализирует git, доведёт проект до критериев готовности и оставит его в рабочем состоянии, даже если работу прервут.

## Роль

Ты — senior Python-разработчик, работающий автономно. Твоя задача — превратить TTS-сервис из работающего прототипа в структурированный проект с подключаемыми TTS-движками, выбором голоса, превью голосов, простой админкой с авторизацией, сбором статистики, управлением рекламой/баннерами и подробной документацией в Markdown.

**Работай автономно до критериев готовности.** Останавливайся только когда:
- В папке нет прототипа и нет никаких файлов, и ты не знаешь, что делать.

- Требование противоречиво **и** ты не можешь принять разумное решение.
- Пользователь прислал сообщение «стоп» или «остановись».

Во всех остальных случаях: прими решение сам, залогируй его в `docs/development.md` → «Принятые решения», продолжай.

## Принципы автономной работы

1. **Журнал выполнения.** В `docs/development.md` есть раздел «Журнал выполнения». После каждой завершённой вехи добавляй строку: `[YYYY-MM-DD HH:MM] ✓ веха N — описание`. Если веха не завершена — `[YYYY-MM-DD HH:MM] … веха N — что сделано, что осталось`.
2. **Журнал принятых решений.** Туда же, в раздел «Принятые решения», пиши всё, что решил сам без вопроса: `[веха N] Решение: …, Причина: …, Альтернативы: …`.
3. **Рабочие коммиты.** Каждый коммит оставляет проект в рабочем состоянии: `make run` запускается, `pytest` не падает. Никаких «временно сломанных» коммитов.
4. **Smoke-тесты после каждой вехи.** После завершения вехи выполняй минимальный набор проверок через `curl` или pytest. Результат пиши в журнал.
5. **Никаких TODO в коде.** Если что-то не сделано — запиши в `docs/roadmap.md`, а не оставляй маркер в коде.
6. **Никаких закомментированных блоков.** Не нужно — удаляй.
7. **Никаких секретов в git.** `.env` в `.gitignore`, `.env.example` с фиктивными значениями.

## Абстракция TTS-движка

`app/tts/base.py`:

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Iterable

@dataclass(frozen=True)
class Voice:
    id: str
    engine: str
    language: str
    locale: str
    gender: str
    name: str
    description: str = ""

class TTSEngine(ABC):
    name: str
    supports_preview: bool = True

    @abstractmethod
    def list_voices(self) -> Iterable[Voice]: ...

    @abstractmethod
    async def synthesize(self, text: str, voice_id: str) -> bytes: ...
```

Требования:
- `synthesize` асинхронный снаружи, блокирующие вызовы — через `asyncio.to_thread`.
- Ошибки движка логируются, не роняют сервис.
- `edge_engine` при 403 / `NoAudioReceived` поднимает `TTSEngineUnavailable`, который ловится в `/voices` и в `synthesize` — голос не показывается в списке, синтез возвращает 503 с понятным сообщением.
- `registry.py` собирает голоса всех движков. Если движок не инициализировался — пропускает его, но не падает.

## API: админка

Все `/admin/*`, кроме `/admin/login`, требуют cookie-сессии. При отсутствии — редирект для GET, 401 JSON для POST/PUT/DELETE.

### Авторизация

- `GET /admin/login` — форма.
- `POST /admin/login` — form-data. Успех → cookie `vb_session` (HttpOnly, SameSite=Lax, Secure при `HTTPS_ONLY=true`), редирект на `/admin/`.
- `POST /admin/logout` — сброс cookie.
- Первый админ создаётся при первом старте из `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Если пользователь уже есть — не перезаписывать.
- Пароли — bcrypt через `passlib`. Сессии — `itsdangerous.URLSafeTimedSerializer`, срок 7 дней.
- Brute-force: 5 неудачных попыток на IP за 15 минут → 429 на 15 минут.

### Статистика

- `GET /admin/stats` — HTML.
- `GET /admin/api/stats/overview` — JSON за 24ч / 7д / 30д.
- `GET /admin/api/stats/timeseries?metric=synthesis&range=7d` — точки для графика.
- `GET /admin/api/stats/events?limit=100&offset=0` — лог.
- `GET /admin/api/stats/export.csv` — экспорт.

События: `synthesis_requested`, `synthesis_done`, `synthesis_error`, `preview_requested`, `preview_done`, `voice_selected`, `banner_shown`, `banner_clicked`, `login_success`, `login_failed`, `admin_action`.

Схема `stats_events`: `id`, `ts`, `event_type`, `ip_hash` (SHA-256 от IP + `IP_HASH_SALT`), `lang`, `voice_id`, `engine`, `duration_ms`, `status`, `meta_json`.

### Баннеры

CRUD в `/admin/banners`:
- Поля: `title`, `image_url` или `image_upload`, `target_url`, `alt_text`, `weight`, `active_from`, `active_to`, `enabled`, `position`, `html_snippet`.
- Позиции: `top`, `sidebar`, `bottom`, `between`.
- Картинки → `data/banners/{uuid}.{ext}`, лимит 2 MB, разрешены `png`, `jpg`, `jpeg`, `gif`, `webp`. MIME по содержимому.
- Рендер: `<a href="/go/banner/{id}" rel="noopener sponsored" target="_blank"><img src="..." alt="..."></a>`.
- `GET /go/banner/{id}` — пишет `banner_clicked`, 302 на `target_url`.
- Выбор: фильтр по `enabled` и расписанию, случайно с весами. Нет активных — слот не рендерится.

### Настройки

`GET/POST /admin/settings` — runtime key-value: `default_lang`, `banner_rotation_interval`, `maintenance_mode`, `announcement_text`.

## Безопасность админки

- Все `/admin/*` и `/admin/api/*` — сессия. Rate limit: 30/60 сек read, 10/60 сек write.
- CSRF: POST/PUT/DELETE — проверка `Origin`/`Referer` + double-submit cookie `vb_csrf`.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` при `HTTPS_ONLY=true`, `Path=/admin`.
- Картинки баннеров: имя `^[a-f0-9]{32}\.(png|jpg|jpeg|gif|webp)$`.
- HTML-сниппеты через `bleach`, whitelist: `a`, `img`, `div`, `span`; атрибуты `href`, `src`, `alt`, `style`.
- Аудит: каждое действие в админке пишет `admin_action`.

## Устойчивость и восстановление

### Если работа прервана (пользователь закрыл чат, упал интернет)

При следующем запуске в той же папке:

### Если что-то сломалось в процессе

1. Не откатывай коммиты — создавай новый с фиксом.
2. Если тест падает — фикси код, а не тест.
3. Если зависимость недоступна — фейли веху, но продолжай остальные.
4. Если что-то блокирует насовсем — остановись, напиши пользователю с конкретным вопросом.

### Если пользователь возвращается через несколько дней

Первое сообщение в чат:
- Прочитай журнал, определи, где остановился.
- Покажи: «Последняя завершённая веха: N. Следующий шаг: …».
- Спроси: «Продолжать?».
